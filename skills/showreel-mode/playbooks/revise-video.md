### 만든 영상 고치기

형제 skill 경로는 mode 폴더 기준이다. 기존 프로젝트와 수정 요청·피드백이 있을 때 쓴다. 기존 마스터와 유료 원본(나레이션·효과음·생성 이미지)은 새 검수가 끝날 때까지 보존한다.

1. 기존 노트·타임라인·검수와 수정 요청을 확인한다.
2. 변경 소비값과 무효화 범위·비용을 의존 그래프에서 정한다.
3. 필요한 leaf를 실행하고 관련 산출물만 다시 만든다.
4. 영향 장면과 완성본을 다시 검수한다.
5. 변경·재사용 근거와 결과물·사람 확인 요청을 전달한다.

**1.** Read `../resolve-showreel-tools/SKILL.md`. `S`·`O`를 확인하고 환경 점검을 실행한다. 프로젝트의 `제작노트.md`, `PAUSE.md`, `script.json`, `timeline.json`, `qa/qa_report.md`, `qa/critique_*.md`, `out/` 납품본을 읽는다. 정리된 프로젝트에는 무음 렌더 `out/video.mp4`와 `audio/mix.wav`가 없을 수 있다. 장면을 다시 렌더해야 하면 엔진 파일의 존재와 `git -C <프로젝트> status --short -- reel/engine.js reel/fx.js`를 확인한다. 엔진 상태는 index와의 diff, `$S/../assets/engine/`과의 `cmp`, 제작노트로 판별한다. Git 밖이거나 미추적이면 보관본과 제작노트를 기준으로 삼는다. 엔진·폰트가 그 영상 때와 다르거나 없거나 엔진 상태를 판단할 수 없으면 adapter의 "옛 프로젝트 복원" 분기를 먼저 한다.

**2.** 아래 표에서 이번 변경이 닿는 행을 고른다. **principle-stable-cues-late-surfaces**를 적용한다. 재사용은 BPM·길이 같은 겉값이 아니라 화면이 실제로 소비하는 값(큐, `music.hitN`, 음악 에너지 곡선, 크레딧 문구, 규격)이 그대로인지로 정한다. 다시 만들 산출물, 재사용할 산출물, 다시 드는 비용(나레이션·효과음 크레딧, 렌더 시간)을 정리한다.

| 변경 | 다시 만들 것 | 재사용 조건 |
| --- | --- | --- |
| 나레이션 문구·보이스·설정 | 바뀐 줄의 나레이션 → `timeline.py` → 그 시각을 쓰는 장면 → 렌더 → 믹스 → 마감 → 검수. 줄 시각이 바뀌면 음악 악보의 나레이션 빈틈을 고쳐 다시 렌더 | 바뀌지 않은 줄의 클립은 그대로(바뀐 줄만 다시 생성) |
| 나레이션·효과음·음악 gain, 덕킹, 리버브만 | (`script.json`의 `gain_db`를 고쳤으면 `timeline.py`) → 믹스 → 마감 → 완성본 검수 | 영상 스트림 전체. 영상을 다시 렌더하지 않는다 |
| 음악 교체·편곡(격자 유지) | op55 렌더·검증 → `timeline.py` → 소비값 비교 → 믹스 → 마감 → 검수 | 새 `timeline.json`·`reel/timeline.js`의 박·다운비트·`music.start`·장면이 쓰는 큐·`music.hitN`·음악 에너지 곡선이 같거나, 그 값을 쓰는 장면이 없을 때만 영상 재사용. 아니면 해당 장면을 다시 렌더 |
| `music.meta.json`의 크레딧 변경 | 납품 크레딧·제작노트. 화면에 보이는 크레딧 문구가 바뀌면 그 장면·조각 렌더 → 마감 → 검수 | 화면 문구가 같을 때만 오디오만 수정 |
| BPM·첫 다운비트·길이·화면이 쓰는 큐 변경 | 분석 → 타임라인 → 영향 장면·경계 → 렌더 → 믹스 → 마감 → 검수 | 영향을 받지 않는 조각 |
| 장면 코드·이미지·폰트·팔레트 | 영향 스틸·비평 → 해당 조각(2분 넘는 영상) 또는 전체 렌더 → 마감 → 검수 | 다른 조각, 오디오 전체 |
| 화면비·규격(예: 9:16) | 레이아웃·안전 영역·장면 → 전체 렌더 → 포스터 → 검수 | 음악·나레이션 길이가 같으면 오디오 재사용. 자동 크롭으로 품질을 대신하지 않는다 |
| 최종 렌더에서만 생긴 섬광·정지 | 해당 카메라·움직임 → 해당 조각 → 최종 움직임 검사 → 검수 | 다른 조각 |

**3.** 표에서 고른 순서대로 leaf를 부른다. 원고·문구는 Read `../plan-video/SKILL.md`, 나레이션·음악·효과음·타임라인은 Read `../prepare-video-audio/SKILL.md`, 장면·이미지·규격 레이아웃은 Read `../build-video-scenes/SKILL.md`, 렌더·믹스·마감은 Read `../deliver-video/SKILL.md`를 따른다.

- 오디오만 고칠 때는 deliver-video의 "오디오만 다시 마감" 분기를 쓴다. 믹스 뒤 줄별 나레이션 대 배경 표에 ✗나 이전보다 내려간 줄이 없는지 확인하고, 기존 마스터와 다른 이름(`_r2`)으로 마감한다. 무음 렌더가 지워졌으면 보존된 마스터의 영상 스트림을 입력으로 쓴다.
- 음악 교체는 prepare-video-audio의 "음악 교체" 분기로 기존 격자를 복구해 새 악보에 쓴다. 표의 소비값 비교 결과로 영상 재사용을 정한다.
- 다른 규격을 만들 때 기존 규격을 계속 다시 렌더할 수 있어야 하면, 프로젝트를 복사한 파생 프로젝트에서 작업하고 유료 오디오는 복사해 재사용한다. 파일 이름에 규격을 붙여 기존 납품본과 구분한다.

**4.** 영향 장면은 Read `../critique-video/SKILL.md`로 같은 시각의 스틸을 다시 뽑아 전후를 비교한다. 장면을 고쳤으면 모든 구간이 "유지"가 될 때까지 3단계와 반복한다. 완성본은 deliver-video의 자동 검수와 최종 시트로 확인한다. **principle-judge-rendered-evidence**를 적용한다.

**5.** deliver-video의 "납품 보고" 형식에 바뀐 것, 다시 만든 것과 재사용한 것의 근거, 새 파일 경로, 기존 납품본을 교체할지에 대한 선택을 적는다. 제작노트의 재생성 명령을 갱신한다. 보고 끝에 mode의 사람 판정 요청 문장을 쓴다. 납품이 끝났다는 것이 삭제 승인을 뜻하지는 않는다.
