# 모션그래픽 영상 제작 mode

이 mode는 요청과 프로젝트 상태를 보고 playbook 하나를 고르고, playbook의 단계마다 leaf skill을 불러 그 결과로 다음 단계를 정한다. leaf는 맡은 결과와 검사 근거, 남은 문제를 돌려주면 끝난다. 반복·재실행·중단은 playbook이 정한다.

다른 skill은 이 mode 폴더의 형제 폴더에 있는 SKILL.md를 읽고 따른다. 도구 경로와 공유 계약은 `../resolve-showreel-tools/SKILL.md`가 정한다.

## 결과물과 판정

| 구분 | 계약 |
| --- | --- |
| 납품 파일 | `out/<제목>_<길이>s.mp4`(마스터), `_공유용.mp4`, `_포스터.jpg`, 나레이션이 있으면 `.srt`, 프로젝트 최상위 `제작노트.md` |
| 재현 근거 | `concept.md`, `storyboard.md`, `research/`, `script.json`, `timeline.json`, `reel/`, `assets/`, 오디오 원본, `qa/critique_NN.md`, `qa/qa_report.md`, `qa/final_sheet*.png` |
| 에이전트 완료 | 납품 파일이 있고 규격이 맞다. 구간 비평이 모두 "유지"다. 최종 시트를 Read로 봤다. 수치 보고의 "고칠 것"을 모두 처리했다. 출처·크레딧·재생성 명령·대체 경로·사람 확인 요청을 납품 보고와 제작노트에 넣었다 |
| 사람 판정 | 영상 전체를 이어서 본 리듬·가독성·의도 전달, 스피커나 이어폰으로 들은 음질·대사·취향 |

납품 보고 끝에 다음 문장으로 사람 판정을 요청한다. 끝내지 못한 항목이 있으면 이 문장 앞에 따로 적는다.

> 위 마스터 파일을 처음부터 끝까지 보고, 스피커나 이어폰으로 소리도 확인해 주세요. 저는 프레임과 수치·STT로 확인했으며 직접 청취하지 않았습니다.

스크립트가 정상 종료했다는 사실만으로 완료라고 쓰지 않는다. 결과물 기준표(요청의 각 부분이 결과물에 요구하는 것)는 `../resolve-showreel-tools/references/contract.md`의 "결과물 기준"에 있다.

## 브리프

브리프는 처음 한 번, 사용자만 아는 사실에 한해서 묻는다. 대상이 누구·무엇인지, 실존 대상의 꼭 넣을 정보(이름 표기, 일시, 장소, URL, CTA), 사용자 자료의 위치다. 무드, 팔레트, 길이, 화면비, 구성, 나레이션 여부, 이미지 사용 여부는 묻지 않고 근거를 붙여 정한 뒤 납품 보고에 적는다. Claude 자신이 대상이면 브리프 질문 없이 시작한다. op55 경로·설치 선택과 ElevenLabs BYOK·유료 Music 사용 범위는 필요할 때 확인한다. 이미 정한 선택은 다시 묻지 않는다. 진행 중 막히는 일(보이스 불가, 확인되지 않는 사실)은 leaf의 대체 경로로 처리하고 납품 보고에 적는다.

요청에 없는 길이·규격·음량 같은 기술 값은 공유 계약의 "기술 기본값"을 쓴다. 사용자가 정한 값과 작업 폴더의 프로젝트 정책(예: 그 폴더의 기본 길이)이 있으면 그것이 먼저다.

## 진행 방식 선택

| 요청과 상태 | playbook |
| --- | --- |
| 새 영상, 또는 기존 영상을 콘셉트부터 새로 만든다 | `playbooks/create-video.md` |
| 이미 만든 프로젝트가 있고 문구·나레이션·음악·믹스·장면·규격을 고친다 | `playbooks/revise-video.md` |

대상 프로젝트가 있는지 모호하면 작업 폴더에서 `제작노트.md`·`script.json`이 있는 프로젝트를 찾는다. 찾지 못하고 요청에서도 알 수 없을 때만 한 번 묻는다.

고른 playbook을 끝까지 읽는다. 줄 맨 앞에 `1. `처럼 번호가 있는 단계 문장만 그대로 todo 첫 항목들로 복사하고, 그 뒤에 이 작업의 세부 항목을 붙인다. todo 도구가 없으면 응답 첫 줄 `단계 n/N:` 다음에 원문을 번호 목록으로 쓴다. 실행하지 않는 단계도 지우지 않고 `skip: 이유`를 남긴다.

## 진행 장부와 운영

진행이 길어지면 프로젝트 폴더에 `PAUSE.md`(끝난 것, 진행 중인 것, 다시 시작하는 순서)를 남긴다. 세션이 끊겨도 다음 세션이 이어받는다.

오래 걸리는 작업(조사, TTS, 음악 렌더, 이미지 생성, 최종 렌더)은 실행 환경의 백그라운드 실행이나 하위 agent로 돌리고 그동안 다음 단계를 진행한다. 정해진 시간만큼 잠들어 기다리지 않는다. 구간이 여러 개인 영상은 구간마다 하위 agent에 나눠 맡길 수 있다(build-video-scenes의 "나눠 만들기").

## 경계

- 음악 경로는 prepare-video-audio가 선택한다. op55가 기본이고, 선택한 ElevenLabs Music BYOK와 내장 합성 fallback을 제공한다. op55를 쓰면 현재 설치본 문서와 파일 계약으로 연결하고 mode를 중첩 호출하지 않는다.
- 모든 작업 파일은 프로젝트 폴더 안에 둔다. 비용·라이선스·삭제 같은 hard constraint는 각 leaf에도 있어 leaf를 직접 불러도 지켜진다.
- 같은 문제를 두 번 겪으면 그 일을 맡은 leaf의 references에 적는다. 새 흐름·기술·판단으로 남길 성공 경험은 사용자가 부를 때만 정리한다.

## Principles

- **콘셉트가 먼저** (`principle-concept-before-template`). 콘셉트·아트 디렉션·장면 기법을 고를 때 도구 목록이나 예전 기본값이 아니라 주제에서 출발한다.
- **렌더한 증거로 판정** (`principle-judge-rendered-evidence`). 화면·소리 품질과 완료를 판정할 때 코드나 종료 코드가 아니라 렌더한 프레임, 수치 표, 독립 비평으로 판단하고 청취는 사람에게 맡긴다.
- **큐는 고정, 표면은 늦게** (`principle-stable-cues-late-surfaces`). 시각을 정하거나 수정 범위를 정할 때 이름 붙은 큐와 격자를 지키고, 화면이 소비하는 값이 바뀌면 다시 렌더한다.
