# 이미지·스타일 프레임·장면

Read ../resolve-showreel-tools/SKILL.md

입력은 `concept.md`, `storyboard.md`, `reel/timeline.js`, 프로젝트 폴더, adapter가 확인한 `S`다. 비평에서 돌아온 경우에는 `qa/critique_NN.md`의 고칠 구간도 입력이다. 결과는 `assets/`의 이미지와 출처 기록, 스타일 프레임 시트, `reel/` 장면 코드와 장면별 스틸, 그리고 바꾼 구간 목록이다. 다음 단계와 반복 여부는 이 skill을 부른 playbook이 정한다.

## 직접 불러도 지킬 것

- 실존 인물의 얼굴·몸은 이미지로 생성하지 않는다. 생성 이미지는 얼굴이 보이지 않는 환경·사물·뒷모습 컷으로 쓴다.
- 실존 회사의 로고·브랜드를 흉내 내지 않는다. 가상 의뢰 구간의 브랜드는 이름과 표장을 새로 만든다. 실존 브랜드가 주제면 공식 색(사이트 CSS·로고)을 쓴다.
- 영상의 숫자·직함·연도는 조사 출처가 있는 것만 쓴다.
- 섬광은 어두운 배경에서 opacity 0.15 이하로 쓰고, 1초에 3번을 넘기지 않는다(광과민성).
- 화면은 시간 t의 순수 함수다. 시각은 타임라인 큐로 건다.
- 제품 화면은 실제 화면을 캡처해 쓴다. 캡처할 수 없을 때만 목업을 그리고 화면에 밝힌다.
- 로그인이 필요한 화면은 사용자가 직접 로그인한다. 로그인 프로필만 프로젝트 밖 임시 폴더에 두고 촬영 뒤 지운다(`references/capture.md`).
- 모든 작업 파일은 프로젝트 폴더 안에 둔다. 검수용 스틸과 시트는 `<프로젝트>/qa/`에 둔다.

## 이미지

원래 6단계다. 콘셉트에 사진이나 생성 이미지가 필요할 때만 한다. `references/images.md`를 읽는다. 제품·서비스·저장소 화면은 생성하거나 그리기 전에 `references/capture.md`대로 실제 화면을 캡처한다.

- 생성: codex-image 스킬의 배치 스크립트로 만든다(5장씩 병렬, 장당 약 1분).

  ```bash
  ~/.claude/skills/codex-image/scripts/codex_imagegen_batch.sh <프로젝트>/assets/gen "프롬프트::이름.png" …
  ```

- 사람이 나오는 사진풍 이미지: `photoreal` 스킬로 프롬프트를 만든다.
- 실제 대상을 닮게 만들 때: `$S/codex_ref_image.sh`로 참조 사진을 붙인다.
- 후처리: `python3 $S/prep_images.py <프로젝트>/assets/gen --out <프로젝트>/assets/img [--cutout]`. 레터박스 제거, 확대, 누끼를 한다.
- 확인: `python3 $S/prep_images.py --sheet <프로젝트>/assets/img --out <프로젝트>/qa/sheet_images.png`로 시트를 만들어 Read로 본다. 손가락·글자·로고가 섞인 이미지는 다시 만든다.

## 스타일 프레임

원래 7단계다. 전체 장면을 쓰기 전에 구간마다 대표 프레임을 1~2장 만들어 한 시트로 본다. 스틸과 시트는 critique-video의 스틸 명령으로 뽑는다.

- 각 프레임을 포스터로 써도 될 수준인가, 구간끼리 서로 다른 작업으로 보이는가, `references/design.md`의 "뻔한 화면"에 해당하는 요소가 이유 없이 들어가 있지 않은가를 본다.
- 기준에 못 미치는 구간은 이 단계에서 방향을 바꾼다. 방향이 둘 이상 떠오르는 구간은 둘 다 만들어 비교한다. 장면을 다 만든 뒤에 방향을 바꾸는 것보다 비용이 적다.

**principle-concept-before-template**와 **principle-judge-rendered-evidence**를 적용한다.

## 장면 제작

원래 8단계다. `references/engine.md`(엔진 API, 장면 작성법, WebGL·3D, 나눠 만들기)와 `references/design.md`(아트 디렉션, 움직임 원칙, 리듬, 한글 타이포)를 읽고 장면을 쓴다. `references/techniques.md`는 검증된 기법 코드 22종이다. 콘셉트가 요구하는 표현이 거기 있으면 코드를 가져다 쓰고, 없으면 새로 만든다. 목록에서 고르는 것으로 장면을 기획하지 않는다.

- 엔진 규칙: 화면은 시간 t의 순수 함수다. `Math.random`, `Date.now`, CSS transition·animation, 이전 프레임 상태에 기대는 코드를 쓰지 않는다. 렌더러가 임의 시각으로 이동하고 여러 워커가 나눠 그리기 때문이다. 물리 시뮬레이션처럼 누적이 필요한 계산은 setup에서 고정 간격으로 미리 계산해 두고 render에서 시각으로 읽는다.
- 표현 수단에 제한을 두지 않는다. DOM·SVG, 캔버스 2D, WebGL2 셰이더, three.js 3D가 모두 렌더된다(`engine.md`의 "WebGL: 셰이더와 3D").
- 시각은 숫자를 직접 쓰지 말고 `REEL.cue('이름')`로 타임라인 큐를 쓴다. 그래야 오디오를 다시 만들어도 화면이 따라온다. **principle-stable-cues-late-surfaces**를 적용한다.
- 하드 컷·상태 전환은 큐보다 0.5프레임 앞에 둔다(`cue(x) - 0.5/fps`). 모션 블러 셔터가 프레임 앞뒤에 걸쳐 있어서, 그래야 큐 프레임에 새 상태가 정확히 보인다. 장면 경계도 같다: `REEL.scene({ start: cue('scene.s02') - 0.5 / REEL.fps, end: cue('scene.s02.end') - 0.5 / REEL.fps, … })`. 정수 초 큐를 그대로 쓰면 `--sub 4` 렌더에서 경계 프레임에 앞뒤 구간이 섞인다.
- 첫 프레임을 어떻게 시작할지는 콘셉트가 정한다. 빈 화면·정적·페이드로 시작한다면 의도를 `concept.md`에 적는다. 의도하지 않은 빈 프레임으로 시작하지 않는다.
- 색은 `concept.md`의 구간별 아트 디렉션을 따른다. 실존 브랜드가 주제면 공식 색(사이트 CSS·로고)을 쓴다. `reel/index.html`의 색 토큰은 회색 자리 표시 값이므로 그대로 두지 않는다.
- 3분 넘는 영상이나 구간이 많은 쇼릴은 구간마다 `scenes_sNN.js`로 나누고 하위 agent에 나눠 맡길 수 있다(`engine.md`의 "나눠 만들기").
- 장면 하나를 쓸 때마다 critique-video의 장면별 스틸 명령으로 시작+0.5 · 큐+0.4 · 끝-0.6초를 뽑아 Read로 본다.

## 고칠 때

비평에서 "고침"이나 "다시 만듦"이 나온 구간만 고친다. 가장 약한 구간은 수치를 조정하기보다 방향을 바꿔 다시 만든다. 고친 뒤 같은 시각의 스틸을 다시 뽑아 전후를 비교한다. 2분 넘는 영상은 고친 구간이 든 조각 번호를 함께 돌려준다(deliver-video가 그 조각만 다시 렌더한다).

화면비·규격을 바꿀 때는 레이아웃과 안전 영역을 다시 설계한다(`design.md`의 "레이아웃과 안전 영역"). `reel/scenes.js`의 `REEL.config` 크기를 바꾸고, 자동 크롭으로 대신하지 않는다. 세로(9:16) 영상은 `fx.js`가 위 250px·아래 420px을 피하므로 직접 그린 요소도 이 영역을 비운다.

## 자주 생기는 문제

| 증상 | 조치 |
| --- | --- |
| 구간들이 서로 비슷해 보임 | 이웃한 구간끼리 매체·팔레트·서체·움직임·질감 가운데 두 가지 이상이 다른지 확인한다. 아니면 약한 쪽 구간의 아트 디렉션을 다시 정한다 |
| 영상이 멈춰 보이거나 밋밋함 | `motion_check.py`가 알려 준 시각이 의도한 정지인지 확인한다. 아니면 새 사건(등장·재배치·카메라 이동)을 넣고, 전경·배경을 다른 속도로 움직이고, 퇴장을 다음 구도로 이어지는 움직임으로 바꾼다 |
| 화면 글꼴이 기본 고딕으로 나옴 | 렌더 로그의 "폰트" 줄 확인, `reel/fonts/fonts.css`에 그 굵기가 있는지 확인 |
| WebGL 화면이 검게 나옴 | 컨텍스트를 `preserveDrawingBuffer: true`로 만들었는지, render 안에서 그리는지 확인한다. 라이브러리는 `reel/lib/`에 파일로 두고 불러온다 |
| 장면 경계에서 빈 화면·잔상 | `contact_sheet.py --around`로 ±3프레임을 보고 퇴장을 컷 0.1초 전에 끝낸다 |
| 세로(9:16) 영상의 HUD·자막이 앱 UI에 가림 | `fx.js`가 세로 영상이면 위 250px·아래 420px을 자동으로 피한다. 직접 그린 요소도 이 영역을 비운다 |
