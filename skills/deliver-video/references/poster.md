# 안내 포스터

영상과 같은 안내(행사, 프로그램, 참여 방법)를 한 장으로 전하는 포스터를 만들 때 쓴다. 영상의 포스터 프레임(`_포스터.jpg`)과는 다른 결과물이다. 아래 기준은 읽히게 하기 위한 것이다. 어떤 서체와 색을 쓸지는 그 영상의 콘셉트와 아트 디렉션이 정한다.

## 그림과 글자를 나눈다

- 이미지 생성 모델에는 그림만 맡긴다. 프롬프트에 글자·숫자·로고를 넣지 말라고 쓰고, 받은 그림에 글자 같은 형태가 생겼는지 Read로 확인한다. 이미지 모델이 쓴 한글은 틀리기 쉽다.
- 글자는 HTML로 조판하고 렌더해 PNG로 만든다. 문구를 고칠 때 그림을 다시 만들지 않아도 된다.
- 그림을 쓰지 않아도 되면 영상의 장면 그림이나 사용자 자료를 쓴다.

## 읽히는 조판

| 항목 | 기준 |
| --- | --- |
| 서체 | 한 가족. 위계는 굵기와 크기로 만든다. 여러 서체를 섞으면 위계가 흐려진다 |
| 색 | 글자색 하나와 강조색 하나(바탕 제외). 항목마다 다른 색, 형광펜 밑줄, 카드 그림자는 강조를 흩뜨린다 |
| 가장 작은 글자 | 세로 2400×3600에서 44px, 가로 1920×1080에서 22px 이상. 다른 크기는 비율로 맞춘다. 공유용 JPG를 휴대폰으로 볼 때도 읽히는 크기다 |
| 반복 정보 | 날짜별 주제, 단계처럼 같은 형식이 되풀이되면 표나 번호 목록으로 쓴다 |
| 문구 | 영상과 같은 사실을 쓴다. 날짜와 요일은 달력으로 대조한다 |

## 세로판과 가로판

- 세로판(2:3, 2400×3600)은 인쇄와 메신저용, 가로판(16:9, 3840×2160)은 화면 상영용이다. 두 판을 함께 낸다.
- 두 판은 내용이 같다. 가로판에서 줄인 문구는 제작노트에 적는다.
- 공유용으로 세로 1200×1800, 가로 1920×1080 JPG를 따로 낸다.

## 렌더

`poster/poster.html`(세로)과 `poster/poster_wide.html`(가로)에 조판한다. 서체는 프로젝트의 `reel/fonts/fonts.css`를 상대 경로로 불러 영상과 같은 파일을 쓴다. 렌더는 `$S/capture.mjs`의 `shots`가 한다. 서체와 그림이 다 불러와진 뒤에 찍는다. 렌더 설정 파일을 `poster/shots.json`으로 남긴다.

```json
{
  "scale": 1,
  "shots": [
    {"name": "poster", "url": "poster.html", "viewport": {"width": 2400, "height": 3600}},
    {"name": "poster_wide", "url": "poster_wide.html", "viewport": {"width": 1920, "height": 1080}, "scale": 2}
  ]
}
```

```bash
node $S/capture.mjs shots <프로젝트>/poster/shots.json --out <프로젝트>/poster/out
ffmpeg -y -i <프로젝트>/poster/out/poster_view_1x.png -vf scale=1200:-1 -q:v 3 <프로젝트>/poster/<제목>_안내포스터_공유용.jpg
```

## 확인

- 공유용 JPG를 Read로 열어 가장 작은 글자가 읽히는지 본다.
- 렌더 결과에서 서체가 기본 고딕으로 바뀌지 않았는지 본다.
- 영상 문구와 날짜·장소·순서가 같은지 대조한다.
- 고친 판은 이전 판을 `poster/v1/`처럼 보관한 뒤 만든다.
- 납품 보고에 인쇄용·공유용 경로를 적고, 인쇄해 볼 사람에게 확인을 요청한다.
