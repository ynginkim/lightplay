# 최종 렌더·믹스·마감·납품

Read ../resolve-showreel-tools/SKILL.md

입력은 비평을 통과한 `reel/`, `timeline.json`, 오디오, adapter가 확인한 `S`다. 결과는 `out/`의 납품 파일, `qa/qa_report.md`와 최종 시트, 처리하지 못한 "고칠 것", 납품 보고, `제작노트.md`, 정리 목록과 합계다. 고칠 구간이 나오면 돌려주고, 어느 단계로 돌아갈지는 이 skill을 부른 playbook이 정한다.

## 직접 불러도 지킬 것

- 최종 렌더 뒤에는 `motion_check.py`를 반드시 다시 돌린다.
- 사운드를 직접 들어 봐 달라고 요청한다. Claude는 소리를 들을 수 없고 수치로만 확인했다.
- 정리는 사용자가 영상을 확인하고 끝났다고 한 뒤에만 하고, 휴지통으로 옮기는 것이 기본이다. 크레딧을 쓴 `audio/vo/`·`audio/sfx/`, 최종 믹스, 음악 악보와 쓰인 음악, `assets/`, 납품본, 재현 코드, 최종 검수 기록은 옮기지 않는다.
- 마감 출력 파일 이름을 입력 영상과 같게 두지 않는다. 새 검수가 끝날 때까지 기존 마스터를 보존한다.
- 모든 작업 파일은 프로젝트 폴더 안에 둔다.

## 최종 렌더·믹스·마감

원래 10단계다.

```bash
node $S/render.mjs --dir <프로젝트>/reel --out <프로젝트>/out/video.mp4 --sub 4 --format png   # 모션 블러. 60초에 약 3~5분, 백그라운드로
python3 $S/mix.py <프로젝트>/timeline.json --verified-music <검수한-WAV>
python3 $S/finish.py --video <프로젝트>/out/video.mp4 --audio <프로젝트>/audio/mix.wav \
  --name "<제목>_<길이>s" --outdir <프로젝트>/out --timeline <프로젝트>/timeline.json
```

2분이 넘는 영상은 구간 경계에서 조각으로 나눠 렌더한다. 장면 코드가 한 줄만 바뀌어도 렌더러는 이전 청크를 모두 버리므로, 조각으로 나눠 두면 고친 조각만 다시 렌더하고 이어 붙일 수 있다. 경계는 `초 × fps`가 정수인 시각으로 고른다.

```bash
python3 $S/render_pieces.py --dir <프로젝트>/reel --out <프로젝트>/out/video.mp4 --cuts 0,51.6,103.2,<길이>        # 전체
python3 $S/render_pieces.py --dir <프로젝트>/reel --out <프로젝트>/out/video.mp4 --cuts 0,51.6,103.2,<길이> --only 2  # 2번 조각만 다시
```

**최종 렌더 뒤에는 `motion_check.py <프로젝트>/out/video.mp4`를 반드시 다시 돌린다.** 모션 블러(`--sub 4`) 때문에 초안에 없던 문제가 생긴다. 출력의 ✗·△를 읽는다.

- 섬광: 선이 많은 화면 위의 빠른 카메라 이동이 여러 프레임에 섞이면서 생긴다. 카메라 가속을 `inOutSine`처럼 부드럽게 바꿔 해결한 사례가 있다.
- 정지: 작은 움직임이 블러에 뭉개져 정지로 잡힌다. 느린 카메라 이동을 더해 해결한 사례가 있다.

고친 구간은 그 조각만 다시 렌더한다. 장면을 고치는 일은 build-video-scenes에 돌려준다.

## 믹스 판단

믹스 기준은 `../prepare-video-audio/references/audio.md`의 "믹스 기준"에 있다.

나레이션에 리버브를 넣지 않는다. 2.4초 홀을 `--hall 0.12`로 걸었던 영상에서 "나레이션에 에코가 너무 많다"는 지적을 받았다. 공간감이 꼭 필요할 때만 `--hall 0.04~0.08`을 쓰고, `mix.py`가 출력하는 "말 끝 잔향"이 ✓(-32dB 이하)인지 확인한다.

`mix.py`는 모든 음악 경로의 나레이션 대 배경 검사를 소유한다. `--verified-music`에 앞 단계에서 검수한 WAV를 명시해 타임라인의 음악과 같은지 확인한다. 검수한 파일 경로를 모르면 먼저 음악 검수 기록을 확인한다. 믹스 실패·빈 표·누락 줄은 미측정이다. 나레이션이 있으면 미측정이 남은 채 마감하지 않는다. 없으면 "나레이션 없음" 사유로 이 검사를 완료 조건에서 제외한다. 줄마다 "나레이션 대 배경" dB를 보여 준다. ✗(6dB 미만)인 줄은 근처 효과음을 줄이거나 핵심 단어에서 0.2~0.3초 비켜 놓고 다시 믹스한다. 오디오만 고칠 때는 영상을 다시 렌더하지 않고 `mix.py`와 `finish.py`만 다시 돌린다.

## 오디오만 다시 마감

gain·덕킹·리버브처럼 오디오만 바뀌었을 때 쓴다. 영상 스트림은 재사용한다.

1. 줄별 `gain_db`처럼 `script.json`의 값을 고쳤으면 prepare-video-audio의 `timeline.py` 명령을 먼저 다시 실행한다(그 값이 `timeline.json`으로 옮겨진다). 그다음 `python3 $S/mix.py <프로젝트>/timeline.json --verified-music <검수한-WAV>`(필요한 옵션과 함께)으로 믹스를 다시 만든다.
2. 믹스 실패나 나레이션이 있는데 표가 비었거나 줄이 빠졌으면 미측정으로 남기고 마감하지 않는다. `mix.py`가 출력한 줄별 "나레이션 대 배경" 표를 이전 마감 때의 표와 비교한다. ✗ 줄이나 이전보다 내려간 줄(✓→△, △→✗)이 있으면 마감하지 않는다. 음악이나 효과음을 키우면 이전에 ✓였던 줄도 △로 내려간다. 그 줄의 `gain_db`를 올리거나 근처 소리를 줄이고 1단계부터 다시 한다. 아래 자동 검수는 이 표를 보지 않아서, 줄이 내려가도 통과로 나온다.
3. 위 `finish.py` 명령으로 마감하되 `--name`을 `"<제목>_<길이>s_r2"`처럼 바꿔 같은 `out/`에 낸다. 이미 `_r2`가 있으면 `_r3`으로 올린다. 같은 이름으로 내면 기존 마스터를 덮어쓰므로, 새 검수가 끝날 때까지 마스터를 보존하라는 규칙을 어긴다.
   - `--video`는 무음 렌더 `out/video.mp4`가 있으면 그것을 쓴다.
   - 정리로 `out/video.mp4`가 지워졌으면 보존된 마스터 `out/<제목>_<길이>s.mp4`를 쓴다. 마스터의 영상 스트림은 무음 렌더와 같다.
4. 아래 자동 검수를 새 파일로 돌린다. 기존 납품본을 새 파일로 바꿀지는 사용자가 정한다.

## 자동 검수

원래 11단계 앞부분이다.

```bash
python3 $S/qa_check.py <프로젝트>/out/<이름>.mp4 --timeline <프로젝트>/timeline.json --script <프로젝트>/script.json --stt
```

규격, 음량, 너무 어두운 구간, 섬광, 멈춘 화면, 완성 믹스의 받아쓰기(숫자 오인식 포함)를 검사하고 `qa/qa_report.md`와 최종 시트를 만든다. "고칠 것"을 모두 처리하고 최종 시트를 Read로 본 뒤 납품한다. STT에서 한 번만 틀린 줄은 한 번 더 돌려 두 번 다 틀릴 때 고친다. 보고를 읽는 법은 `../critique-video/references/qa.md`의 "자동 검수(qa_check.py) 읽는 법"에 있다. 이 검수는 보고서를 쓰고도 정상 종료하므로 종료 코드가 아니라 보고의 "고칠 것"을 읽는다. **principle-judge-rendered-evidence**를 적용한다.

## 납품 보고

원래 11단계다. 납품 보고와 `제작노트.md` 형식은 `../critique-video/references/qa.md`의 "납품"에 있다. 다음을 반드시 넣는다.

- 산출물의 **절대 경로 표**
- 구간 구성표와 고른 콘셉트, 버린 후보
- Claude가 정한 것(무드·길이·나레이션 여부 등)과 요청과 다르게 반영한 것
- 공개 전 확인할 것: 사진 사용 허락, 단일 출처 사실, 시점이 지나면 틀리는 정보, AI 생성 인물이 가상이라는 점
- 실제 음악 제공자·설정·fallback 사유와 출처·크레딧. op55를 썼으면 현재 음악의 meta 크레딧, API를 썼으면 모델·사용량과 미확인 과금 여부
- 재생성 명령
- 사운드를 직접 들어 봐 달라는 요청. Claude는 소리를 들을 수 없고 수치로만 확인했다.

## 납품 뒤 정리

5분 영상 한 편이 작업 파일로 4GB를 넘게 쓴다. 납품 보고를 마치면 지울 목록부터 본다. 규칙은 `../critique-video/references/qa.md`의 "납품 뒤 정리"에 있다.

정리하기 전에 이 프로젝트에서 새로 만든 효과음을 공용 라이브러리에 등록한다. 내용이 같은 소리는 건너뛴다.

```bash
python3 $S/sfx_library.py add <프로젝트>    # 새 효과음을 공용 라이브러리에 등록
python3 $S/cleanup.py <프로젝트>            # "다시 안 쓸 것"과 "후속 작업용" 목록과 크기만 보여 준다
python3 $S/cleanup.py <프로젝트> --apply    # "다시 안 쓸 것"을 휴지통으로 옮긴다
```

1. 두 갈래의 목록과 합계를 납품 보고에 붙인다. "후속 작업용"(무음 렌더, 렌더 조각, 음악 스템, 녹음 원본)은 나레이션·음악만 고쳐 다시 마감할 때 쓴다고 적는다.
2. 사용자가 영상을 확인하고 끝났다고 하면 `--apply`로 "다시 안 쓸 것"을 휴지통으로 옮긴다. "후속 작업용"까지 정리하라고 하면 `--apply --followup`을 쓴다. 녹음 원본은 다시 받을 수 없으니 그 목록을 따로 보이고 확인받는다. 휴지통이 아니라 바로 지우라는 요청에만 `--delete`를 더한다. 납품 완료만으로 정리 승인을 받았다고 보지 않는다.
3. 정리한 뒤 `제작노트.md`에 옮긴 것, 휴지통 경로, 다시 만드는 방법을 한 줄 적는다.

`cleanup.py`는 납품본(포스터 JPG가 있는 이름)이 없으면 아무것도 지우지 않는다. 그 안전장치를 끄는 옵션은 일반 절차로 쓰지 않는다.

## 자주 생기는 문제

| 증상 | 조치 |
| --- | --- |
| 나레이션에 에코·울림이 많음 | `--hall` 없이 `mix.py`와 `finish.py`만 다시 돌린다(영상 재렌더 불필요). 리버브를 남길 때는 `mix.py`의 "말 끝 잔향"이 ✓일 때까지 `--hall`을 낮춘다 |
| 완성 믹스에서 말이 묻힘 | 타격음을 핵심 단어에서 0.2~0.3초 비키기, 해당 줄 `gain_db` +2~3, `--duck` 0.8 |
| 최종 렌더에서만 섬광·정지가 나옴 | 모션 블러 탓이다. 그 구간의 카메라 가속을 부드럽게 하거나 사건을 더하고, `render_pieces.py --only`로 그 조각만 다시 렌더한다 |
| 공유용 음량이 마스터보다 낮음(-17 LUFS 등) | 예전 `finish.py`가 마스터의 AAC를 다시 인코딩하며 피크 보정이 과하게 걸렸다. 지금은 `--audio` 원본에서 인코딩한다. `finish.py`를 다시 돌린다 |
| 영상이 yuvj420p·풀레인지로 나옴 | `render.mjs`와 `finish.py`를 거치면 yuv420p·tv로 나온다. 다른 도구로 인코딩하지 않는다 |
